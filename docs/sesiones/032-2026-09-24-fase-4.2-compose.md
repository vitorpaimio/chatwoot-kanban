# Sessão 032 — Fase 4.2: Compose/Nginx

## Escopo autorizado

Implementar e validar o segundo adaptador no Mac, reutilizando o instalador
Swarm. Recriar laboratório Docker temporário e removê-lo ao final, mantendo
código e Chatwoot nativo anterior. Nenhum commit, push ou publicação solicitado.

## Implementação

- `Deployment.adapter` mantém Swarm como padrão e acrescenta Compose, projeto
  Chatwoot, endereço/porta de escuta. Configuração ambígua e TLS não certificado
  são recusados. Exemplo em `deploy/installer.compose.example.json`.
- `ComposeRuntime` resolve serviço por projeto e nome; `ComposeLifecycle` herda
  planejamento, contas, backup, matrícula cifrada, restore e uninstall. Núcleo
  recebe pontos de extensão de infraestrutura sem duplicar regras de negócio.
- Projeto próprio com PostgreSQL, migração, API, worker e Nginx, encaminhando
  Chatwoot e Kanban na mesma origem. SSE sem buffering e WebSocket encaminhado.
- Propriedade verificada para containers, rede privada e volume; redes externas
  e imagem Chatwoot não são alteradas. Remoção preserva dados e atributos por
  padrão, com purge explícito somente de recursos próprios.
- Bind mounts Compose de infraestrutura em diretório 0700/arquivos 0600. Bootstrap
  lê como root e troca UID/GID/HOME; processo API observado com UID 10001.
  Tokens humanos e técnicos não são persistidos em arquivos de teste.
- Estado Swarm anterior sem novos campos continua compatível. Recursos fora da
  lista de mounts gerenciados são preservados na desinstalação.

## Ensaio

Roteiro opt-in `tests/contracts/phase42_compose.py`; navegador real em
`tests/browser/phase42.cjs`; preparo descartável em `deploy/compose-lab/prepare.py`.
Contexto `colima-kanban-phase42`, projeto Chatwoot `cwcompose`, projeto Kanban
`kanban-compose`. Docker Engine 29.5.2, Compose 5.5.1, Nginx 1.28.3, Chatwoot CE
4.18.0, ARM64, HTTP em localhost:18080. Chatwoot fixado no digest da fase 4.

O ensaio encontrou HOME apontando para `/root` após a troca de UID: asyncpg
falhava ao procurar a chave TLS padrão. Corrigido para o HOME do usuário 10001;
instalação repetida passou depois da correção. O roteiro de navegador precisou
finalizar o marcador de onboarding da conta sintética e usar o campo de e-mail
real (input textual sem label associada). Também passou a selecionar o submenu
Kanban, pois Pipeline apenas expande/recolhe o menu. Nenhuma dessas correções
exigiu modificar o Chatwoot. A execução foi retomada após instalação repetida,
conservando as evidências anteriores.

Resultado: instalação repetida com recibo estável; sessão humana no navegador e
quadro integrado; bloqueio anônimo/de outra conta; webhook nativo processado;
worker parado detectado; atualização preservando configuração; imagem inexistente
bloqueada e restore recuperando valor anterior e saúde; uninstall com token
revogado, atributos/volume preservados e repetição; reinstalação no mesmo volume;
purge removeu apenas dois atributos próprios e manteve `kanban_etapa` preexistente.
Loader e containers Kanban removidos; Chatwoot Compose seguiu ativo até a limpeza.

Gates: Ruff, 158 testes Python no PostgreSQL exclusivo (dois opt-in de outras fases
omitidos), quatro testes JavaScript, sintaxe do roteiro de navegador e diff limpo.
O ensaio Compose/navegador real foi executado separadamente. Evidência pública
sem credenciais em `docs/phase42-evidence.json`.
